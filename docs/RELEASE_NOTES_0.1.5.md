# AI Memory 0.1.5

本次为 macOS 与 Windows 对齐修复版本，解决候选规则批准后反馈滞后、重复生成规则，以及系统临时工作目录混入历史列表的问题。相对 GitHub 上的 v0.1.3，本版本还包含此前准备于 v0.1.4 的主窗口恢复修复。

## 候选规则审批

- 批准过程中显示“处理中…”，并禁用同一候选的操作按钮，避免连续点击重复提交。
- 写入成功后立即移除待审卡片并显示成功提示，再刷新候选、已批准规则和仓库待审计数，不再等待 Wiki、实体图谱等无关数据刷新。
- 数据库端防止重复或并发审批生成多条规则。
- 拒绝、暂缓采用相同的处理状态与刷新方式；旧请求不会覆盖已提交的审批结果。
- 写入成功但列表刷新失败时，明确区分两种状态。

## 系统临时目录过滤

- 自动导入跳过项目路径位于 `/tmp`、`/private/tmp`、`/var/tmp`、`/private/var/tmp`、`/var/folders`、`/private/var/folders` 的会话。
- 已收录的临时项目不再显示于默认历史列表、搜索结果及项目历史搜索中；既有数据库记录和原始历史文件保留。
- 判断依据为项目路径，而非历史文件的存储位置。正常项目内名为 `tmp` 的目录，以及 Gemini 的 `.gemini/tmp` 历史存储位置，不会仅因名称而被过滤。
- 显式恢复与同步写入保留原有数据处理能力。

## 主窗口恢复

- 主窗口使用固定标识并保留可恢复的窗口引用，关闭窗口时隐藏而非丢失窗口。
- Dock、菜单栏入口和重复启动复用主窗口；窗口被释放时重新创建，避免应用仍在运行却找不到主界面。

## 验证与数据保护

- macOS 测试套件 74 项通过，覆盖审批幂等性、临时目录分类、历史导入及现有同步、迁移和回收站行为。
- 隔离数据窗口已实测批准：待审数从 1 变为 0，已批准规则从 0 变为 1，并显示成功提示。
- 本版本不自动清理此前重复生成的已批准规则，不删除用户历史、配置或凭据。

## 下载与安装

- `AI-Memory-0.1.5-macOS-universal.dmg`：支持 Apple silicon 与 Intel Mac，要求 macOS 14 或更高版本。
- `AI-Memory-0.1.5-macOS-universal.dmg.sha256`：安装包的 SHA-256 校验文件。

使用项目固定的本地代码签名身份，尚未使用 Apple Developer ID 公证。首次打开受到 macOS 拦截时，请通过“系统设置 → 隐私与安全性”确认打开。安装包不包含用户数据库、历史、设置、凭据或私钥。

## Windows

Windows 客户端同步升级至 0.1.5（包版本 0.1.5.0），在此 release 中提供 `AI-Memory-0.1.5-Windows-x64-Setup.exe` 和 `.sha256`，保留上方 macOS DMG。

- 候选审批按 ID 防重，独立连接并发和重复批准只关联同一条规则；重复请求明确返回已有结果。
- 成功提交后移除候选并先显示反馈，后台仅刷新审批集合及仓库计数；刷新失败明确提示已写入。
- 默认列表、搜索、项目分组、MCP 项目历史及自动导入过滤 Windows 实际临时目录和同步的 POSIX 临时路径；匹配大小写及目录边界，保留正常项目的 tmp 子目录及 Gemini 缓存中的合法历史。
- 不删除既有临时历史和重复规则；显式读取、恢复、迁移和同步继续保留原始数据。
- 132 项 Windows 核心测试、x64/ARM64 Release 构建及 MCP 协议检查通过。ARM64 本轮提供构建验证，下载的 EXE 安装程序为 x64。
- Windows 安装程序未进行商业代码签名。升级前建议保留旧安装包和数据库备份。

macOS tag 保持原提交；Windows 安装包从 Windows 最终提交构建，来源提交在 GitHub release 中单独注明。
